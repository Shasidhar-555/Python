TASK B3.4 — ENGINEERING TRADE-OFFS & RUNNING ACCUMULATOR COMPLEXITY
======================================================================================
Architectural Recommendations:
  • For Quick One-Time Ad-Hoc Analysis: Use Pandas.
    Reason: Rich vectorized API (groupby, describe, resample), high-level plotting integration,
    and zero database setup required for exploratory data science.
  • For Daily Automated Production Reporting: Use SQLite / Relational Database with B-Tree Index.
    Reason: Bound memory footprint (O(1) disk paging), multi-process ACID concurrency, instant
    incremental ingestion, and 10x-50x faster queries via index caching.

Alternative Concept Analysis: Single-Pass Running Accumulator vs List Storage:
  1. Implemented Solution (Single-Pass Running Accumulator):
     - Updates sum and count in-place: acc[key] = [sum + val, count + 1].
     - Time Complexity:  O(N) linear scan.
     - Space Complexity: O(stations × days) — only holds aggregated bucket sums.
  2. Alternative Solution (Storing All Raw Readings):
     - Appends every reading to a list: store[key].append(val), then calls statistics.mean().
     - Time Complexity:  O(N) linear scan.
     - Space Complexity: O(N) — stores all 1,051,200 individual float objects in RAM.
     - Memory Savings: Single-pass reduces RAM by (8,760 / 365) = 24x factor!
