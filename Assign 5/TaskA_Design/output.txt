TASK A1: DESIGN THE DATA ACQUISITION (City Air-Quality Monitoring Network)
======================================================================================
A1.1 — Inspect the Source & Expected Data-Quality Problems:
  • Missing / Blank Readings  : e.g. '2026-10-01,14,,45,22,30.5' | Sensor packet dropped or connection timeout; yields empty string '' or 'NA'.
  • Negative Sensor Values    : e.g. '2026-10-01,03,-12.4,18,10,24.0' | Physical concentration of matter cannot be negative; indicates calibration failure.
  • Impossibly Large Values   : e.g. '2026-10-01,18,9999.0,80,45,28.0' | Exceeds physical atmospheric ceiling (e.g. PM2.5 > 1000 µg/m³).
  • Unit Inconsistency        : e.g. '2026-10-01,12,45,80,30,86.0' | Station reports 86.0°F instead of 30.0°C; distorts regional thermal statistics.
  • Duplicate Telemetry Rows  : e.g. '2026-10-01,08,55,90,32,27.0' | Same station, date, and hour repeated multiple times with identical or conflicting values.
  • Corrupted Delimiters / Garbage: e.g. '2026-10-01;09;50;85;NA' | Semicolons instead of commas, non-ASCII characters, or truncated line buffers.

A1.2 — Relational Database Schema Design (SQLite):
-- Master station registry table
    CREATE TABLE IF NOT EXISTS stations (
        station_id TEXT PRIMARY KEY,
        station_name TEXT NOT NULL,
        zone TEXT NOT NULL,
        latitude REAL,
        longitude REAL,
        native_temp_unit TEXT DEFAULT 'C'
    );

    -- Cleaned hourly telemetry readings table
    CREATE TABLE IF NOT EXISTS readings (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        station_id TEXT NOT NULL,
        reading_date TEXT NOT NULL,      -- ISO-8601: YYYY-MM-DD
        hour INTEGER NOT NULL,           -- 0 to 23
        pm25 REAL,                       -- µg/m³
        pm10 REAL,                       -- µg/m³
        no2 REAL,                        -- ppb
        temperature REAL,                -- Standardized Celsius (°C)
        pm25_minmax REAL,                -- Normalized [0, 1]
        pm25_zscore REAL,                -- Standardized (mean=0, std=1)
        FOREIGN KEY (station_id) REFERENCES stations(station_id),
        UNIQUE(station_id, reading_date, hour)
    );

    -- Composite B-Tree index for instantaneous spatial-temporal queries
    CREATE INDEX IF NOT EXISTS idx_station_date ON readings(station_id, reading_date);
    CREATE INDEX IF NOT EXISTS idx_date_hour ON readings(reading_date, hour);

A1.3 — CSV vs SQL Architectural Comparison for Typical Board Questions:
  • Q1: Average PM2.5 of Adyar in October
    - CSV Approach: Scan 12 daily CSVs per day (372 files), parse strings in Python loop.
    - SQL Approach: SELECT AVG(pm25) FROM readings WHERE station_id='Adyar' AND reading_date LIKE '2026-10-%';
    - Evaluation:   SQL is ~80x faster via B-Tree index scan.

  • Q2: Top 3 polluted stations by monthly PM10
    - CSV Approach: Load all files into memory, build dictionary in Python, sort keys.
    - SQL Approach: SELECT station_id, AVG(pm10) FROM readings GROUP BY station_id ORDER BY AVG(pm10) DESC LIMIT 3;
    - Evaluation:   SQL engine executes optimized in-engine hash aggregate & sort.

  • Q3: Hourly diurnal trend across all stations
    - CSV Approach: Read all rows, bucket by hour in Python defaultdict, compute mean.
    - SQL Approach: SELECT hour, AVG(pm25) FROM readings GROUP BY hour ORDER BY hour;
    - Evaluation:   SQL aggregates millions of rows in milliseconds using disk paging.

TASK A2: DESIGN THE CLEANING AND NORMALISATION
======================================================================================
A2.1 — Formal Cleaning Rules & Justifications:
  • Missing Values (PM2.5, PM10, NO2):
    - Action:        If isolated (gap <= 2 hrs), apply Linear Forward Fill (LOCF); if gap > 2 hrs, impute with station diurnal median for that hour; drop if entire day missing.
    - Justification: Preserves diurnal continuity without distorting variance or peak rush-hour signals.

  • Impossible Values (< 0 or > 999):
    - Action:        Mark as NULL / invalid. Impute using median of preceding and succeeding valid readings if isolated; otherwise treat as missing.
    - Justification: Eliminates extreme ADC spikes and negative sensor drift while preventing catastrophic mean distortion.

  • Duplicate Telemetry Rows:
    - Action:        Retain the first valid transmission record matching (station_id, reading_date, hour); discard subsequent duplicates.
    - Justification: Prevents double-counting in daily averages caused by automatic cellular re-transmissions.

  • Fahrenheit Temperature Readings:
    - Action:        Detect if station is in {'Guindy_F', 'Marina_F'} or if temp > 50°C: convert via C = (F - 32) * 5 / 9.
    - Justification: Standardizes ambient thermal measurements to Celsius across all 12 monitoring stations.

A2.2 — Normalisation Design:
  1. Min-Max Normalisation: x' = (x - x_min) / (x_max - x_min)
     - Scales readings into bounded [0, 1] range.
     - Best suited for visual heatmaps, neural network inputs, and bounded air-quality index scales.
  2. Z-Score Standardisation: z = (x - µ) / σ
     - Centers distribution at mean=0 with unit variance=1.
     - Best suited for statistical anomaly detection, outlier z-score thresholds (|z| > 3), and multi-station regression modeling.

A2.3 — Canonical Data Formatting Standards:
  • Dates:    ISO-8601 string format 'YYYY-MM-DD' (e.g. '2026-10-15').
  • Hours:    Integer in range [0, 23].
  • Stations: Canonical Title Case string (e.g. 'Adyar', 'Guindy', 'Anna Nagar').
  • Numbers:  IEEE 754 64-bit floating point rounded to 2 decimal places for reporting.

A3.1 — Justified Chart Selections for Board Inquiries:
  • Trend of PM2.5 over a Month:
    - Selected Chart: Time-Series Line Chart with 7-Day Moving Average
    - Justification:  Continuous line shows day-to-day fluctuations, seasonal weather shifts, and high-pollution episodes over time.

  • Comparison Across 12 Stations:
    - Selected Chart: Station Box Plot (Five-Number Summary + Outliers)
    - Justification:  Directly visualizes median, interquartile range (IQR), variance spread, and extreme spikes across all 12 monitoring stations.

  • Temperature vs PM2.5 Relationship:
    - Selected Chart: Bivariate Scatter Plot with Polynomial / Linear Trendline
    - Justification:  Reveals correlation and meteorological phenomena such as thermal inversion (low winter temperatures trapping surface particulate matter).

  • Hours with Worst Air Quality:
    - Selected Chart: 24-Hour Diurnal Bar Chart / Area Chart with Peak Rush Hour Shading
    - Justification:  Identifies diurnal peaks during morning (08:00–10:00) and evening (18:00–21:00) vehicular congestion windows.

A3.2 — Daily Station Summary Table Schema:
  Columns: [station_id, reading_date, valid_hours, min_pm25, max_pm25, mean_pm25, std_pm25, aq_category]
  Production: Generated via single SQL aggregate query: SELECT station_id, reading_date, COUNT(pm25), MIN(pm25), MAX(pm25), AVG(pm25) GROUP BY station_id, reading_date.

A5.1 — Citizen Complaint Sentiment Scorer & Extractive Summarizer:
  • Lexicon Sentiment Scorer: Maintains POSITIVE, NEGATIVE, and NEGATOR sets.
    Algorithm: Tokenizes text into lowercase tokens; maintains state flag 'negate'. If previous word is in NEGATORS, flips the sign of next sentiment word.
  • Extractive Summarizer: Frequencies of non-stopwords are computed.
    Sentences are ranked by sum of constituent word frequencies. The top-k sentences with highest density of thematic keywords are extracted.

A5.2 — Rule-Based Keyword Chatbot & Architectural Limitations:
  • Architecture: Regex/Keyword matching state machine extracting: (1) metric (PM2.5, temperature), (2) station name, (3) temporal keyword (today, yesterday, month).
    Executes parameterized SQL query and constructs natural language response.
  • Critical Limitations:
    1. Brittle to typos, colloquialisms, and regional spelling variants ('Adayar' vs 'Adyar').
    2. Cannot handle multi-turn conversational context or follow-up questions.
    3. Complete failure on out-of-domain queries or compound intent questions.

ALGORITHM CleanAndIngestAirQualityData(csvFileList, dbConnection)
// Standard: SIMATS Engineering Algorithmic Standard
BEGIN
    DECLARE rawBuffer AS LIST OF RECORD
    DECLARE cleanBuffer AS LIST OF RECORD
    DECLARE validMinMax AS RECORD(minVal: REAL, maxVal: REAL)

    FOR EACH csvFile IN csvFileList DO
        OPEN csvFile IN READ MODE WITH ENCODING "utf-8" AS stream
            DECLARE reader AS CSV_DICT_READER = InitializeReader(stream)
            FOR EACH row IN reader DO
                DECLARE station AS STRING = Trim(row["station"])
                DECLARE readingDate AS STRING = Trim(row["date"])
                DECLARE hour AS INTEGER = ToInteger(row["hour"])
                DECLARE rawPM25 AS STRING = Trim(row["pm25"])
                DECLARE rawTemp AS STRING = Trim(row["temperature"])

                // Anomaly Filter: Missing and Impossible values
                IF rawPM25 = "" OR rawPM25 = "NA" THEN CONTINUE END IF
                DECLARE pm25 AS REAL = ToFloat(rawPM25)
                IF pm25 < 0.0 OR pm25 > 999.0 THEN CONTINUE END IF

                // Unit Standardization: Fahrenheit to Celsius
                DECLARE temp AS REAL = ToFloat(rawTemp)
                IF station ENDS WITH "_F" OR temp > 50.0 THEN
                    temp <- (temp - 32.0) * (5.0 / 9.0)
                END IF

                APPEND RECORD(station, readingDate, hour, pm25, temp) TO cleanBuffer
            END FOR
        CLOSE stream
    END FOR

    // Calculate Normalisation Bounds
    DECLARE minPM25 AS REAL = ComputeMin(cleanBuffer, "pm25")
    DECLARE maxPM25 AS REAL = ComputeMax(cleanBuffer, "pm25")
    DECLARE meanPM25 AS REAL = ComputeMean(cleanBuffer, "pm25")
    DECLARE stdPM25 AS REAL = ComputeStdDev(cleanBuffer, "pm25")

    // Batch Database Insertion with Parameterized SQL
    BEGIN TRANSACTION
        FOR EACH rec IN cleanBuffer DO
            DECLARE normMinMax AS REAL = (rec.pm25 - minPM25) / (maxPM25 - minPM25)
            DECLARE normZScore AS REAL = (rec.pm25 - meanPM25) / stdPM25
            EXECUTE SQL "INSERT OR REPLACE INTO readings VALUES (?, ?, ?, ?, ?, ?, ?)" 
                    WITH (rec.station, rec.readingDate, rec.hour, rec.pm25, rec.temp, normMinMax, normZScore)
        END FOR
    COMMIT TRANSACTION
END ALGORITHM
